# ING-02 — Single-document HTML/TXT from source intake to answers

**Status:** Implementation in progress. Backend, frontend, migrations and disposable database fixtures are in place; complete browser and real-model acceptance remains to be exercised.

**User outcome:** An administrator can add one HTML page or plain-text document by upload or public HTTP/HTTPS URL, inspect and correct its extracted content, record rights, publish and index it, then ask a question and reopen an exact saved citation in the original saved document. Preview alone is not an import.

**PRD basis:** Product roadmap sections 36, 40.1–40.6 and 42; POC PRD section 64, especially the requirement that each format have a complete usable slice. Builds on [ING-01](ING-01.md). This task includes the HTML/TXT portion of the shared reader and RAG work described in ING-05. Keep existing PDF intake, rights, publication, Quick/Deep retrieval and saved citations working.

## Complete feature slice

1. **Intake and provenance.** Extend the existing Add source UI and administrator-only Go API to accept `.html`/`.htm` and `.txt` files and one public HTTP/HTTPS document URL. Reuse the ING-01 fetcher for URL imports, including its redirect, destination, TLS and decompressed-size checks. Re-fetch on import; do not treat previewed bytes as a durable asset. Detect format from bytes and response metadata rather than extension alone. Show a useful mismatch, binary, login/error, empty-content or size-limit outcome; retain form values on failure and clear source-specific metadata after success. Record requested and final URL, acquisition time, transport, detected format, content hash, immutable original bytes and revision. An HTTP acquisition is visibly marked unencrypted. Uploaded HTML must not fetch embedded resources or links.
2. **Durable background processing.** Queue the import through PostgreSQL jobs and existing worker leases. Persist progress and failure details so browser navigation, worker restart and retry do not create duplicate assets or duplicate embeddings. Store raw HTML/TXT privately; never serve raw HTML as executable same-origin content. Keep source and edition metadata, source asset, processing revision and document locator relationships explicit. Do not fill PDF path, page count or page-index fields with invented values to fit the old schema. Migrate only the storage and API contracts needed for these formats while preserving PDF citations.
3. **Format-aware extraction.** For static HTML, decode the declared/supported charset, extract substantive headings, paragraphs, lists and table content in reading order, retain stable anchors and section context, and remove scripts, forms and repeated navigation from evidence. For TXT, support UTF-8 and BOM-signaled Unicode, preserve paragraph/line boundaries and original offset mapping, and show an encoding override when detection is uncertain. Reject undecodable/binary input rather than silently replacing characters. Preserve raw bytes and a mapping from normalized text spans to original sections/offsets. Flag empty JavaScript shells, uncertain boundaries and structure that a generic adapter cannot preserve; do not certify repertory grades from flattened text.
4. **Extraction review and publication.** Add a section/block review view with sanitized inert original-versus-extracted text, warnings, and an explicit accept/correct/exclude decision. Corrections create a new processing revision and invalidate affected approvals or index candidates; previously published revisions and saved citations remain intact. Apply existing source-rights, access, text-quality and publication gates. A successful parse is not automatically published. Unknown structure, missing text, unresolved encoding and missing rights remain visible blockers.
5. **Index, answer and reader.** Chunk accepted text at meaningful section boundaries, preserving heading and table context for retrieval while keeping exact quoted passage text and offsets separate. Adapt lexical and embedding index paths and source filters so published, compatible HTML/TXT sources are available in Quick and Deep answers. A saved citation identifies source, asset, revision, section or text span and exact passage, with no fabricated PDF page. Its reader opens the saved revision, highlights the cited span, shows the original URL when available, and still works if the remote page changes or disappears. Validate passage text/offsets on citation resolution and retain current access restrictions. Unsupported questions must produce insufficient evidence rather than unsupported claims.

6. **Automatic literature classification and research scope.** Implement roadmap section 42.1 category values and independent metadata dimensions across existing PDF and new HTML/TXT sources. Allow multiple source categories, reviewed section overrides for mixed works and an unclassified fallback for existing records. Automatically suggest categories from extracted content, headings/layout and metadata after text becomes available across PDF and HTML/TXT intake. Show detected category, supporting reason and uncertainty; persist classifier version, input revision and decision provenance. Low confidence, conflicting signals or classifier failure must expose an unclassified/manual-selection state without failing import. Admins can accept, override or select multiple categories; preserve their choices across retries and record changes. Reference-only metadata suggestions stay provisional. Apply roadmap section 42.1 threshold, review and backfill rules. Add editable intake/review fields, Sources badges/filters and Ask category filters. Apply source/category intersections in every Quick/Deep query, preserve explicit scope on empty results, and save category/revision snapshots and coverage limitations with answers/evaluation reports. Label retrieved evidence by literature category and evidence category. Classification edits follow publication/index invalidation rules without rewriting saved answers. Generic extraction must preserve available heading/style evidence and expose structure readiness separately; category selection alone cannot certify rubric associations or grades.

## Boundaries

- Structured remedy entries, rubric/remedy/grade records, alias resolution and category-aware research routing belong to [ING-06](ING-06.md), the next slice after this task. Until then, only validated text supports passage answers; unknown repertory structure must produce a limitation or insufficient evidence for structured questions.
- This task handles one selected document per import. Linked HTML discovery, page selection, chapter coverage and partial collection recovery belong to ING-03. The UI may suggest that an index needs collection, but must not imply one-page import covers the whole work.
- General XML/JATS intake belongs to ING-04; the existing ALTO path must keep working. ING-05 extends the shared reader/RAG behavior to XML and cross-format coverage rather than deferring HTML/TXT answer readiness from this task.
- Do not use browser-side HTTP fetching, JavaScript execution, unrestricted crawling, automatic rights approval, live-site scraping workarounds, or same-origin raw HTML rendering. Keep PDF's 250 MiB limit and the existing DOI/archive policies.

## Acceptance

- Automatically classify representative materia medica, repertory and another literature category using content, including a misleading title and mixed work. Low-confidence/unreadable input and classifier failure display a manual category selector and retry action. Admin correction survives retries, is audited, refreshes affected current index/filter metadata and leaves historical answers unchanged. Verify reference-only suggestions never become full-text evidence; choosing unclassified preserves eligible general passage research.

- Classify an existing PDF, HTML materia medica, a repertory source and a mixed work; confirm unclassified fallback and section override behavior. Sources/Ask filters intersect with selected source IDs in both Quick and Deep, including generated subqueries; empty results do not broaden scope. Saved answers/evidence retain category snapshots after metadata changes. A repertory label never implies verified grades.

- An authorized administrator imports a static HTML upload, an HTTP-only HTML URL and a TXT upload or URL. Each moves from queued processing to extraction review, explicit rights decision, publication and compatible READY index. No preview request creates a source. The UI shows format, source/revision identity, transport and progress.
- One published HTML source and one published TXT source contribute relevant passages to both Quick and Deep answers when selected. A different source that is unreviewed, denied, failed, superseded or incompatible contributes none. Unsupported questions return insufficient evidence. Saved answer citations reopen the exact section/span in the saved original revision without another model call or a live fetch.
- A changed remote page does not alter an imported snapshot or old citation. Reimport creates a reviewable candidate/revision. Existing PDF citation IDs and original-page links still resolve after migration and reindexing.
- A wrong extension/content type, binary TXT, malformed encoding, empty or login page, oversized response, HTML script/form content, and unsupported structure have explicit review or failure outcomes. Private/redirect/rebinding destinations remain blocked by the shared fetcher. Unauthorized upload, import, review and asset reads fail.
- Focused extraction, locator, import/job-recovery, retrieval and citation fixtures pass; the relevant Go suite and frontend build pass. Exercise the complete UI journey with small permitted HTML and TXT documents and record source/asset/revision IDs plus citation examples. Record live URL checks separately from fixtures; do not claim general website collection from a one-page check.

**Following slice:** [ING-06](ING-06.md) delivers structured repertory and materia medica research under roadmap section 42. Then ING-03 adds bounded linked HTML collection and coverage/recovery controls. ING-04 adds schema-aware XML. ING-05 extends non-PDF reader/RAG contracts and acceptance across XML and multi-document sources. PROD-01 recovery and operational alerts remain deferred while this research core work proceeds.
